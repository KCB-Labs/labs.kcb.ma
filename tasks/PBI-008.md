# PBI-008: Relationship Validation + Publishing Filters + Slug Stability + Seed Fixtures

## Directive
Make the relationship system trustworthy and testable. Implement `src/lib/content/validate.ts` (or `relationships.validate()`) that walks every collection's relationship fields and throws a descriptive error naming the broken ref (e.g., `Project "operant" references nonexistent Lab "ai-employes"`) when a linked slug has no target. Wire validation to run at build (e.g., called from a build-time script or from each `get*` helper's validation mode) so `npm run build` fails on broken refs instead of silently rendering empty. Add shared slug helper `src/lib/content/slugs.ts` (`slugify(title) → lowercase-stable`, plus `assertSlugStable(publishedSlug, proposedSlug)` guard). Consolidate fixtures into a coherent seed graph: at least one Lab `ai-employees` linked to one Research, one Experiment (outcome VALIDATED), one Project `operant` (originLab ai-employees), one Article referencing them, one Person and one Organization linked to that Lab/Project, and one Open Source linked to the Project — proving traversing Lab↔Research↔Experiment↔Project↔Article ↔ People/Orgs. Add unit tests for validation, publishing filter, and slug stability.

- Spec: `specs/content-model/spec.md`
- Depends on: PBI-007

## Verification
- Spec §Contracts: unit test `invalid-project-fixture` with `originLab: nonexistent-lab` causes `validate()` to throw naming the broken relation; `npm run build` with that fixture fails with same message (reviewer can temporarily break a fixture to confirm)
- Publishing filter test: fixtures include matching `published:false` entries for Labs/Projects/Articles that `getLabs()`/`getProjects()`/`getArticles()` hide and `includeDrafts:true` reveals
- Slug test: `slugify("AI Employees") === "ai-employees"`, and updating a published entry's title does not mutate its published slug unless explicitly overridden — test via helper; stability guard throws on accidental slug change for `published:true`
- Seed graph traversal test: `getResearchByLab('ai-employees').length >=1`, `getExperimentsByResearch(researchSlug)`, `getProjectsByLab('ai-employees')` includes `operant`, `getArticlesByLab('ai-employees')` includes the seeded article, `getLabBySlug('ai-employees')` reports its related people/orgs, numbers computed from helpers match fixture counts (proves homepage Numbers can be derived, not hard-coded)
- `cmd /c "npm.cmd run check"` + `cmd /c "npm.cmd run build"` pass with valid seed; images in fixtures have `alt` text where present
- No new page rendering logic introduced
