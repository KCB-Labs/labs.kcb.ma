# PBI-021: Performance + Accessibility Pass (WCAG 2.2 AA, Core Web Vitals)

## Directive
Make the site fast and inclusive before launch. For performance: confirm Astro HTML-first with near-zero client JS on non-island pages, lazy-load below-the-fold images via Astro `<Image />` `loading="lazy"`, defer analytics script, optimize fonts (subset/preload), keep islands on `client:visible`/`idle`, and keep bundles measurable and small (no large UI libs without ADR). For accessibility: audit all public routes (`/`, `/labs/[slug]`, `/projects/[slug]`, `/journal/[slug]`, `/about/*`, `/participate/*`, `/contact`) for WCAG 2.2 AA — semantic HTML, one `h1` per page, correct `h2`/`h3` hierarchy, landmarks (`main`/`nav`/`header`/`footer`), keyboard Tab order with visible focus, accessible menus/comboboxes/forms, sufficient contrast via tokens, descriptive links, `alt` text, `aria-live` for search, `prefers-reduced-motion` disables filter/timeline transitions, and islands degrade gracefully without JS for core content. Record Lighthouse + axe results in the PR.
