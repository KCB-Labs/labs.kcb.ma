# PBI-022: Security Headers, Analytics Abstraction, Error Pages

## Directive
Harden trust boundaries and polish failure states. Add Astro middleware (`src/middleware.ts`) or Node adapter config to emit HTTP security headers (`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY` or `SAMEORIGIN`, `Referrer-Policy: strict-origin-when-cross-origin`, CSP baseline if feasible) and ensure HTTPS-only assumption (HSTS note for Coolify). Implement abstracted analytics adapter `src/lib/analytics.ts` (events: `project_viewed`, `lab_viewed`, `article_viewed`, `github_clicked`, `sponsorship_clicked`, `collaboration_submitted` behind `track(event)`; provider Plausible/Umami swappable via env/adapter without touching pages/islands). Create on-brand error pages `src/pages/404.astro` + `src/pages/500.astro` (404 copy "This path hasn't become a project yet." variant, both with minimal nav back to `/`/`/labs`/`/projects`) plus content-not-found/broken-relation branded fallback. Audit that no secrets leak to client bundles.
