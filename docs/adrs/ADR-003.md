# ADR-003: Relationship-first content model

## Status

Accepted (2026-08-27)

## Context

KCB Labs documents how ideas evolve: IDEA → LAB → RESEARCH → EXPERIMENT → VALIDATION → PROJECT. Content must show these connections, not just list entities independently.

## Decision

Core entity graph: Lab → Research → Experiment → Project → Open Source, with People/Organizations/Technologies as cross-cutting context. Articles reference multiple entity types. Relationships stored as Keystatic relationship fields; validated at build time.

## Alternatives

- **Flat content (no relationships):** Rejected — loses the evolutionary narrative.
- **Graph database:** Rejected — overkill for file-based content, adds infrastructure.
- **Tag-only associations:** Rejected — too loose, no traversal semantics.

## Consequences

- Every page can show related entities (Lab → its Research, Experiments, Projects)
- Broken relationships fail the build, not silently empty
- `src/lib/content/relationships.ts` provides traversal helpers
- Future: knowledge graph visualization is architecturally possible
