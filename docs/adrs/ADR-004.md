# ADR-004: React islands only where interactivity required

## Status

Accepted (2026-08-27)

## Context

Astro renders everything as server HTML by default. Some features need client-side JavaScript (search, filters, timeline). Over-using React defeats Astro's zero-JS-by-default philosophy.

## Decision

Default to Astro components for all server-rendered UI. Add React islands (`src/components/react/`) only when `Does this require client interactivity? → yes`. Use weakest viable hydration: `client:visible` > `client:idle` > `client:load`.

## Current Islands

| Island | Hydration | Why |
|---|---|---|
| `Search.tsx` | `client:visible` | Live search with keyboard nav |
| `Filters.tsx` | `client:visible` | Toggle filters with URL param sync |
| `Timeline.tsx` | `client:visible` | Keyboard navigation, scroll-into-view |

## Alternatives

- **React for everything:** Rejected — ships unnecessary JS to every page.
- **Vue/Svelte islands:** Rejected — React already in stack, no justification for second framework.
- **HTMX/alpine:** Rejected — less ecosystem, team familiarity with React.

## Consequences

- Most pages ship near-zero client JS
- Islands hydrate progressively on visibility
- Bundle size remains small and measurable
- Each new island requires justification in PBI/ADR
