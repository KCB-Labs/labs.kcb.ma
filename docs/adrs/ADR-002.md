# ADR-002: Keystatic local dev / GitHub prod storage

## Status

Accepted (2026-08-27)

## Context

Content needs to be editable via Keystatic admin UI. In development, local file writes are convenient. In production, changes should commit to the repository so Coolify auto-deploys.

## Decision

Keystatic `storage: local` in development, `kind: github` in production (via `KEYSTATIC_GITHUB_CLIENT_ID/SECRET` env). Content lives in `src/content/{collection}/*` as `.mdoc` files.

## Alternatives

- **GitHub-only dev:** Rejected — slow feedback loop, requires network for local editing.
- **Headless CMS (Contentful, Sanity):** Rejected — adds external dependency, vendor lock-in.
- **Local-only (no prod CMS):** Rejected — editorial team needs web-based editing.

## Consequences

- Dev: Keystatic writes directly to filesystem, instant feedback
- Prod: Keystatic commits to GitHub, triggers Coolify deploy
- Content is always git-tracked
- Must protect `/keystatic` with GitHub OAuth in production
